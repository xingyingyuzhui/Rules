## Muse、Muse Code 与 Meta AI 的覆盖关系

| 功能 | 当前依据 | 现有规则 / 依赖 |
| --- | --- | --- |
| Muse 网页 / App 与客户端 VM 连接 | [Muse 官方公告](https://about.fb.com/news/2026/09/introducing-muse-personal-ai-agent/)、[官方安全架构](https://security.muse.ai/)说明客户端连接专属 VM；公开脚本补充 VM 主机解析证据。 | `muse.ai`、`metaaivm.com`，加本次两个精确隐私传输主机。官方架构文章没有提供完整网络白名单。 |
| Muse 认证和入口 | `muse.ai` 的公开访问可进入 `auth.muse.ai`；官方公告 / 安全页引用 `applink.muse.ai`、`security.muse.ai`；安全说明重定向到 `research.meta.ai`。 | 均已被 `muse.ai` 和 `meta.ai` 后缀覆盖，不添加重复子域。共享 Meta 登录和 CDN 仍需相应规则。 |
| Model API、Muse 系列模型与 Muse Code | [Model API 概览](https://dev.meta.ai/docs/overview)、[Muse Code](https://dev.meta.ai/docs/muse-code)、[认证说明](https://dev.meta.ai/docs/muse-code/auth)。 | `api.meta.ai/v1` 和开发者入口都已由 `meta.ai` 后缀覆盖。模型命名变化不产生新的域名规则。 |
| Muse Code 安装 / 更新与设备授权 | 只读检查官方 [`install.sh`](https://dev.meta.ai/install.sh) 与其默认 [`muse-launcher.sh`](https://api.meta.ai/muse-launcher.sh)。启动器使用 `api.meta.ai` 通道 / 启动器、`auth.meta.com` 设备授权，并把安装包下载地址限定到 `lookaside.facebook.com`。 | API 与认证由 AI 列表覆盖；`lookaside.facebook.com` 属共享下载主机，由 `Meta.list` 的 `facebook.com` 后缀处理。没有执行安装、下载程序包、申请设备码或登录。 |
| Meta AI 消费端 | [当前官方产品页](https://ai.meta.com/meta-ai/assistant/)列出网页、移动端、Mac Beta、眼镜和社交 App；没有提供新增的完整消费端网络白名单。 | `meta.ai`、`ai.meta.com` 及现有 Meta 共享域名；平台入口变化本身不需要新增根域。 |
| 共享账号与资源 | [Meta Account 公告](https://about.fb.com/news/2026/04/meta-account/)说明 Accounts Center 的升级；未登录访问 `auth.meta.com/login`，并核对 `accountscenter.meta.com` 认证重定向和 `static.xx.fbcdn.net` 静态资源。 | 两个精确账号主机继续保留；共享 `fbcdn.net`、Facebook / Instagram API 由 Meta 列表处理。新称谓不代表可以删除旧登录主机。 |

只引用 `MetaAI.list` 仍不等于完整覆盖 Muse / Meta AI / Muse Code。推荐沿用 README 的 AI 优先、Meta 随后顺序；需要一致出口时，将两个策略组选为同一具体节点。Muse 在云端 VM 访问第三方网站的出口由其服务端决定，本地代理规则不能直接控制那部分云端出站流量。

- 验证两个列表的字段、域名、重复项、后缀冗余，及 Meta 单文件对 AI 全部匹配范围的覆盖。
